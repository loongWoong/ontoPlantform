# 本体模型是数据库表的结构吗？是 ER 图、类图吗？

不是。数据库表、ER 图、类图描述的是“数据怎么存、结构怎么摆”，本体模型描述的是“概念是什么、概念之间有什么语义关系、什么必然成立”。ER 图和类图通常没有统一的形式逻辑语义，一般按封闭世界理解；本体（尤其是 OWL）有明确的形式语义（开放世界假设、无唯一名称假设），可以被推理机用于分类、一致性检查和隐含知识推导。两者可以互相映射，但不能画等号。

## 本体就是分类法（Taxonomy）吗？

不是。分类法只是概念的 is-a 层次，是本体的一部分。完整的本体还包含对象属性、数据属性、公理、约束，乃至个体数据。如果只需要维护一棵“类目树”，通常用 SKOS 或简单 RDFS 就够了，不必上升到 OWL。

## 本体就是知识图谱吗？

不完全等同。知识图谱通常可以理解为：本体（模式/术语层）+ 实例数据（实体、关系、属性值）+ 可选的推理。本体回答“可以说什么”，知识图谱还回答“实际有什么”。反过来，没有显式本体的知识图谱也可以存在（轻量 schema 或 schema-less），只是语义互操作与推理能力会弱一些。

## 本体必须用 OWL 吗？

不是。本体是“形式化的共享概念体系”，RDFS、SKOS、SHACL，甚至属性图的 schema 与应用层约束，都可以承担本体的部分职责。选择取决于需要多少推理与互操作能力：

- 只要术语与分类：SKOS 或 RDFS。
- 需要一致性检查、类推理、隐含关系推导：OWL 2。
- 主要需要数据完整性校验与业务规则：SHACL。
- 团队使用属性图：LPG 模式 + 应用层约束。
- 面向 Web 的轻量标注：schema.org + JSON-LD。

形式化程度越高，表达与推理能力越强，但建模成本、学习成本和推理成本也越高。各标准的分工与选型见[标准与语言总览](/spec/)。

## 本体模型与 DDD 的领域模型是什么关系？

两者都从领域问题出发，但侧重点不同：

- 领域模型关注如何解决业务问题，强调行为、聚合、不变量与限界上下文。
- 本体模型关注共享概念与数据语义，强调显式定义、互操作、推理与校验。

它们可以共存：用领域模型实现业务，用本体统一语义和集成数据。参见[总览](/main)与[DDD 指南](https://ddd-fans.github.io/ddd-guideline/main)。

## 本体模型要描述到什么程度？

够用即可：能支撑能力问题、能指导数据与应用即可。不是越形式化越好，也不是越细越好。过度建模会带来维护负担、评审困难和推理成本，反而拖慢落地。
