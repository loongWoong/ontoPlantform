## 一、结论先说

后端 79 个单测全绿、全链路可用；**问题 100% 集中在前端表达层**。三条根因：

| 根因 | 表现 | 违反 |
|------|------|------|
| **R1 信息架构照抄后端领域，没有照 §41 收敛** | 8 个平级页签（概览/本体/数据/能力/应用/业务数据/AI 助手/审计），没有 §41 要求的「设置」；「运行时/投影/invoke/Kernel」直接印在界面上 | §41、§42 第一原则 |
| **R2 没有布局系统，只有"卡片 + flex-wrap 兜底"** | 全站 0 个 `<form>`、42 个控件只有 1 个 `<label>`（可见字段带常驻 label 的比例是 0）、54 处内联 `style`；控件靠 `flex:1 + min-width:110px` 挤，挤不下就换行 → 表单散成 2~3 行楼梯 | §42 第二原则 |
| **R3 只做了"定义表单"，没做"产品界面"** | 后端已支持的视图字段/术语别名/应用描述/步数控制前端从不发送；后端有的成员治理没有入口；结果区一次重渲染就被清空 | §21-23、§29、§42 第三原则 |

**一句话**：现在的页面是"把 API 参数摊在屏幕上"，不是"把一件事做完的界面"。

## 二、实测证据（1440×900 / 1280×800 / 1024×768，已播种数据的工作空间）

### 2.1 布局几何

| 指标 | 实测 | 判定 |
|------|------|------|
| 固定头部占高（header 60 + tabs 51） | **111px**，首屏内容从 y=155 开始 | 900px 高的笔记本上，未滚动就被吃掉 17% 高度 |
| 应用页（1440） | 22 个控件 / **0 个有 label** / 23 个按钮 / 27 处内联 style | 三列布局每列约 365px 宽，却塞 3~5 个控件 |
| 应用页控件宽度 | 别名 **81px**、对象类型 **84px**、过滤 JSON **114px**、Agent 目标 136px | 1024 宽时进一步压到 72px，等于不可用 |
| 应用页换行的表单行 | **8 行**（最多 1 行 5 个控件跨 3 行） | "加视图/加查询/加 Agent" 三个动作全部散架 |
| 本体页（1024） | 关系名/源/目标各 **130px**、本体描述 **110px**、术语 110px | 中文 placeholder 被截断成"目标对象，如 TollStati" |
| 能力页调用行（1440） | 3 个输入 346px + 按钮跨 2 行 | 参数 JSON 输入框和按钮不在一行 |
| 数据页投影行 | 3 个控件跨 **3 行**（84/86/163px） | 创建投影的按钮单独占一行 |
| `.grid.cols-2` 卡片高度 | 左 764px vs 右列三张卡 318+190+225 | grid 强制等高 → 右侧底部大片空白 |
| 宽表压力（14 属性 × 6 行） | 表格 **2099px**，整页横向滚动 **1118px**，无 `overflow-x` 宿主，表头 `position: static` | 真实投影对象动辄十几个属性，一张表就能把整个页面推横向滚动 |
| 内联样式 | 54 处 `style="..."` | 布局无法统一调，改一处要改全站 |

### 2.2 交互与状态

| 场景 | 实测 | 问题 |
|------|------|------|
| 连点两次「创建」工作空间 | **创建了 2 个** | 无 in-flight 禁用，重复提交无防护 |
| 应用页运行查询后，再点「加视图」 | 查询结果 **448 字符 → 0**（整块被清空），输入框里刚打的字也丢了 | `loadApplications()` 全量重渲染，结果与草稿一起被抹掉 |
| 打开一个对象详情 | 1 次 get + **N 次 related 串行 await**（`showObject` 在 for 循环里 await） | 关系越多越慢，且是串行而非并发 |
| 未配置 LLM 时的警告条 | 高 **251px**、465 字，占首屏 28% | 用文案代替了界面设计 |
| 能力实现提示 | 194 字常驻 + placeholder 同样 194 字重复一遍 | 同一段技术说明渲染两次 |
| 映射 JSON 输入框 | 高 **115px**（约 6 行），骨架 placeholder 265 字 | 写映射要一边滚动一边对字段 |
| Toast | 6 条堆叠高 **410px**，不可手动关闭 | 错误信息看不到、关不掉 |
| 键盘/无障碍 | 0 个 `<form>`（Enter 不提交）、全站 1 个 `<label>`、除装饰层 `aria-hidden` 外无任何 ARIA/role、5 个 `span[onclick]` | 不能用键盘走完任何一条流程 |

### 2.3 完成度（后端有、前端没有）

| 后端能力 | 状态 |
|----------|------|
| `View.title / properties / query_alias` | API 支持，前端**从不发送** → `openView()` 里 `if (v.query_alias)` 是**死分支**，视图永远只能"整类型全字段表格" |
| `Vocabulary.aliases` | API 支持，前端无输入项 |
| `Relation.description`、`Application.description`、`Workspace.description` | API 支持，前端无输入项 |
| 应用 Agent `max_steps` / `goal` 覆盖 | API 支持，前端只有 AI 助手页能设步数 |
| `llm.script`（Echo 演示 Provider） | API 支持，前端无入口 → 没有真 LLM 就无法演示 Agent 链路 |
| `AddMember`（viewer/editor/owner 治理） | 用例层已实现，**api.py 没有路由** → Web 上完全不可达（design §46 权限 ✅ 落空） |
| 审计 `limit`、变更流分页、find 分页 | 前端硬编码 / 无上限全量渲染 |

### 2.4 语言（§42 第一原则）

静态可见文案 1883 字里出现：**运行时 ×10、Kernel ×8、投影 ×10、invoke ×2、RuntimeGateway ×1、Gateway ×2、static/sqlite/rest、`Type/Id`**；
JS 渲染串里：**alias ×24、JSON ×16、ref ×15、key ×11、published ×5**。
§42 明确点名 `Runtime / Function / Workflow` 不该出现在界面上，现状是把它们当标题用。

### 2.5 与 `docs/completeness-review.md` 的分歧

该评审把 **§41-42 前端信息架构与三原则标为 ✅**，本次实测不成立：

| 它的判断 | 实测 |
|----------|------|
| "业务语言" | 静态可见文案里 运行时×10 / Kernel×8 / 投影×10 / invoke×2，还有 `Type/Id`、`RuntimeGateway` 直接上屏 |
| "复杂度折叠（实现详情/LLM 配置）" | 只有 LLM 配置进了 `<details>`；能力实现的 194 字技术说明**常驻可见**且在 placeholder 里重复一遍；创建能力表单默认展开全部字段 |
| "AI 入口" | Ask/Agent 只存在于「AI 助手」一个页签，其余 7 页无任何自然语言入口（§42 第三原则要求每页可用） |
| "§41 信息架构" | §41 要求纵向列表 + 「设置」；实际是 8 个顶部平级页签且**无设置页** |

它的 A1/A2/A3（成员管理 / deprecate·revise / aliases 未暴露）与本方案一致，已分别并入本方案 C8 / P2 / C7。
结论差异的根源：那是一次**代码存在性**审阅（能力写了吗），本方案是**界面可用性**实测（用户用得上吗）。

## 四、目标设计：简洁前端

### 4.1 骨架（对齐 §41 的纵向 IA）

```
┌────────────┬───────────────────────────────────────────────────┐
│ 232px 侧栏 │ 56px 顶栏：工作空间 ▾ │ 搜索 320 │ ● 状态 │ LLM 徽标 │
│            ├───────────────────────────────────────────────────┤
│ 工作台     │                                                   │
│ ── 业务世界│   主区：max-width 1180，padding 20/24/96          │
│  本体      │   （列表在左，编辑在右 380px 粘性面板）           │
│  数据      │                                                   │
│  能力      │                          右抽屉 420px（覆盖式）   │
│  应用      │                          详情/预览/试运行         │
│ ── 平台    │                                                   │
│  AI 助手   │                                                   │
│  设置      │                                                   │
└────────────┴───────────────────────────────────────────────────┘
```

关键尺寸决策（都要写进 `:root` 令牌，禁止内联 style）：

| 令牌 | 值 | 说明 |
|------|-----|------|
| `--nav-w` | 232px（折叠 64px） | 取代 51px 顶部页签条；固定头部 111px → **56px**，900px 屏多回 55px 首屏 |
| `--top-h` | 56px | 只放：工作空间选择、全局搜索、连接状态、LLM 徽标 |
| `--stage-max` | 1180px | 主内容宽；1440 屏两侧留 130px，行长可控 |
| `--panel-w` | 380px | 页内"编辑/创建"右栏，粘性；窄于现在 578px 的半屏卡片 |
| `--drawer-w` | 420px（详情）/ 720px（视图预览） | 覆盖式，不挤压列表 |
| `--modal-w` | 560px（确认）/ 720px（编辑器） | 发布确认、JSON 编辑 |
| `--field-label-w` | 96px | `.field{display:grid;grid-template-columns:96px 1fr;gap:8px 12px}` |
| `--w-xs/sm/md/lg` | 88 / 132 / 180 / 240px | 枚举、别名、名称、描述；JSON/代码一律 `1fr` 全宽 |
| `--ctl-h` | 32px（sm 26px） | 所有控件同高，行高不再被 placeholder 撑 |
| `--ta-h` | 120px（代码 240~320px，可 resize） | 映射/实现 JSON 至少 10 行可见 |
| `--gap` | 4/8/12/16/24/32 | 只允许这 6 档 |
| `--radius` | 10px（卡片）/ 6px（控件） | 卡片内边距 18px 20px（现 26/28 偏松） |

其余规则：

* `.grid{align-items:start}` —— 不再强制等高，消灭大片空白。
* 表格统一包 `.table-wrap`；单元格 `white-space:nowrap;text-overflow:ellipsis` + `title` 悬浮全文；长值用 `<code>`。
* Toast 最多同时 3 条、宽 320px、可点关闭、错误 8s / 成功 3.5s。
* 提示条 >120px 高视为文案问题：改为 1 行摘要 + `<details>` 展开。
* 保留现有暖色编辑风（配色/字系/低饱和语义色不变），**只动结构与尺寸**，不重做视觉。

**⑤ 应用**（改动最大）

```
┌ 240px 应用列表 ┬────────────── 主舞台（1fr）──────────────┐
│ 运营工作台 ●  │ [视图] [查询] [Agent] [能力]  ← 子页签 40px │
```
