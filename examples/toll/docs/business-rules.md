# 业务规则（计费与拥堵判定）

## 1. 通行费计费

```
通行费 = max(最低收费, 里程 × 车型费率) × ETC 折扣
```

| 车型 | 费率（元/公里） | 最低收费（元） |
|------|-----------------|----------------|
| 客车 | 0.45 | 5.00 |
| 货车 | 0.90 | 8.00 |

- 里程取「入口收费站 → 出口收费站」的固定里程表（同一对站点往返同价）。
- ETC 折扣：从 `lane_type = ETC` 的车道驶出时，总价再乘 `0.95`；走 MTC 不打折。
- 金额四舍五入保留 2 位小数。样例库中的 `passes.fee` 就是按该规则生成的。
- 入口站与出口站不能相同（同站进出属于异常交易，样例库不生成）。

样例校验（可手工复算）：

| 交易 | 车型 | 里程 | 车道 | 计算 | 结果 |
|------|------|------|------|------|------|
| P0003 | 客车 | 158 km | MTC | `max(5, 158×0.45)=71.10` | 71.10 |
| P0004 | 客车 | 384 km | ETC | `max(5, 384×0.45)=172.80` × 0.95 | 164.16 |
| P0002 | 货车 | 336 km | ETC | `max(8, 336×0.90)=302.40` × 0.95 | 287.28 |

## 2. 收费站状态判定

`stations.status` 取以下三档：

| 状态 | 含义 | 判定条件（任一满足） |
|------|------|----------------------|
| `free` | 畅通 | 出口车道平均排队 < 50 米，且实际通行量 ≥ 设计能力的 80% |
| `busy` | 繁忙 | 出口车道平均排队 50~200 米，或通行量为设计能力的 60%~80% |
| `congested` | 拥堵 | 出口车道平均排队 > 200 米，或通行量 < 设计能力的 60% |

运营口径补充：

- 排队长度按 5 分钟滑动平均统计，只统计出口车道（入口拥堵单列，不影响该字段）。
- 状态由运营中心每 5 分钟刷新一次，样例库中为某一时刻的快照，不随时间自动变化。
- 状态是 `TollStation.status` 的取值，业务上口语直接说「拥堵」「畅通」，
  本体术语表把「拥堵」映射到 `TollStation.status`。

## 3. 关系与一致性约束

- 每条车道必须隶属唯一收费站（`lanes.station_id` → `stations.id`）。
- 每条通行交易的 `plate` 必须存在于 `vehicles`，`entry_station` / `exit_station` 必须存在于 `stations`，
  `lane_id` 必须是出口站的一条出口车道。
- 本体侧：`enters` / `passes` 的 source 是 `Vehicle`，`exits` 的 source 是 `TollTransaction`，
  `has_lane` 的 source 是 `TollStation`；投影把行内的两个 id 端点连成关系边。
